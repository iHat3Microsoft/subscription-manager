# Архитектурный план развития (Future Plans)

## 1. Безопасность инфраструктуры и отказ от мастер-SSH ключей

### Проблема текущей схемы:
Если центральный сервер подписок держит у себя приватные SSH-ключи от всех зарубежных и российских VPS-нод для запуска `wg genkey` / добавления пиров, компрометация сервера подписок автоматически означает компрометацию всей сети серверов.

### Целевая архитектура (Zero-Trust к серверу подписок):
1. **Автономность нод:**
   - На серверах VPN (AWG 3.1, VLESS, Hysteria2) ключи выпускаются локально.
   - **Hysteria 2:** переход от одного общего пароля к динамической аутентификации через `auth: userpass` или `auth: command` (проверка по локальной SQLite базе или легкий API-запрос к бэкенду без раскрытия root-доступа).
   - **WireGuard / AWG 3.1:** генерация пула предварительно созданных ключей (pre-generated keypool) — скрипт на VPS создаёт 50-100 готовых пиров и складывает их в зашифрованный буфер. Сервер подписок лишь забирает свободный слот.
2. **Безопасность репозитория (Open-Source готовность):**
   - В коде репозитория отсутствуют любые реальные IP-адреса, домены, токены пользователей и хэши.
   - Домен подписок передаётся строго через переменную окружения `BASE_URL`.
   - Все файлы пользователей хранятся в `data/`, которая находится в `.gitignore`.

## 2. Telegram Bot и WebApp (Mini App)

### Дизайн-система (Omarchy Matte Black / Nautilus):
- Базовый холст: `#121212`, карточки: `#1a1a1a`, границы: `#222222`.
- Золотой янтарный акцент: `--accent-primary: #e68e0d`, hover: `#f5b90a`.
- Текст: мягкий белый `#ebebeb`, второстепенный `#8d939e`.

### Принципы приватности в UI:
- **Никаких имён пользователей на экране.**
- Только технические данные сессии:
  - Статус: `Активна` / `Истекает`
  - Полоса трафика: `Использовано: X GB / Y GB`
  - Срок действия: `До DD.MM.YYYY`
  - Кнопка «Подключить в приложение» (`clash://install-config?...`)
  - Кнопка «Скопировать ссылку»

### Логика работы бота (grammY, Long Polling):
1. **Безопасность:**
   - Бот не слушает внешние веб-порты (никаких Webhook с открытым HTTP наружу), работает через Long Polling.
   - Строгий whitelist `ADMIN_IDS = [...]` для команд администрирования.
2. **Инвайт-система:**
   - Админ вводит `/invite 30d 100GB`.
   - Бот генерирует одноразовую ссылку `t.me/bot?start=inv_HASH`.
   - При переходе пользователя бот генерирует токен, создаёт директорию в `data/`, привязывает `telegram_id` и отдаёт кнопку Mini App.
3. **Привязка существующих пользователей:**
   - Существующий юзер отправляет `/bind <ТОКЕН>`.
   - Бот проверяет существование `data/<USER>/token.txt` и сохраняет Telegram ID в `data/<USER>/meta.json`.

## 3. Десктопное ПО: исключение Яндекс.Браузера и шпионского софта

### Контекст:
На Android `tun.exclude-package` (526 пакетов) исключает российские приложения из TUN-интерфейса на уровне ОС. На Windows/macOS/Linux эта опция игнорируется.

### Реализация для ПК:
Для изоляции Яндекс.Браузера и аналогичного софта от VPN-туннеля добавляются процессные правила в начало `my-rules.yaml`:
```yaml
# Исключение браузеров РФ из туннеля (всегда идут напрямую)
- PROCESS-NAME,browser.exe,DIRECT
- PROCESS-NAME,yandex.exe,DIRECT
- PROCESS-NAME,service_update.exe,DIRECT
```
*(Или `REJECT`, если требуется полностью блокировать их активность при включенном VPN).*

## 4. Схема доставки конфигураций через Angie

- Запросы браузеров на `/configs/<TOKEN>` отдают веб-страницу `sub.html` с `Content-Type: text/html` без заголовка `Content-Disposition: attachment`.
- VPN-клиенты (Clash Meta, FlClash, Verge) получают чистый YAML с `Content-Disposition: attachment; filename="$sub_filename"`.
- Лимиты и таймеры берутся из автогенерируемого файла `public/.sub_info.map`.
